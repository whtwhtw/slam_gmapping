# SLAM 系统信号流、控制流与执行流

本文档描述 ROS2 gmapping SLAM 系统中数据的流动方向、控制逻辑和执行时序。

---

## 一、信号流 (Signal Flow)

信号流描述系统中各节点之间的**数据传递**关系。

### 1.1 总体信号流图

```
用户输入 (teleop_twist_keyboard / 游戏手柄)
        │
        │ /cmd_vel (geometry_msgs/Twist)
        ▼
┌────────────────────┐
│ odometry_publisher │
│   (模拟里程计)      │
└────────┬───────────┘
         │ 1. TF: odom → base_link  (nav_msgs/Odometry + tf2)
         │ 2. /odom (nav_msgs/Odometry) [可选]
         ▼
┌──────────────────────────────────────────────────┐
│              TF2 Buffer (tf2_ros::Buffer)         │
│         维护: odom → base_link 变换               │
└────────────────────────┬─────────────────────────┘
                         │
                         ▼
┌──────────────┐    /scan (sensor_msgs/LaserScan)    ┌──────────────────────┐
│ laser_driver │ ──────────────────────────────────→ │   slam_gmapping      │
│ (真实硬件)    │                                     │   (SLAM 核心节点)     │
└──────────────┘                                     └────────┬─────────────┘
                                                              │
                        ┌─────────────────────────────────────┤
                        │                                     │
                        ▼                                     ▼
              /map (nav_msgs/OccupancyGrid)        TF: map → odom
                        │                                     │
                        ▼                                     ▼
              ┌──────────────────┐              ┌─────────────────────┐
              │  rviz2 (显示)     │              │  TF2 Buffer (全局)   │
              │  /map_metadata   │              │  供导航栈使用        │
              │  /entropy        │              └─────────────────────┘
              └──────────────────┘

              dynamic_map 服务 (nav_msgs/GetMap)
              ←── 外部节点按需请求当前地图 ──→
```

### 1.2 各节点详细信号流

#### A. odometry_publisher 节点

```
输入: /cmd_vel (geometry_msgs/msg/Twist)
      - linear.x: 线速度 (m/s)
      - angular.z: 角速度 (rad/s)

处理: 数值积分
      pose.x     += v * cos(theta) * dt
      pose.y     += v * sin(theta) * dt
      pose.theta += w * dt

输出:
      1. TF: odom → base_link  (tf2_ros::TransformBroadcaster)
         - 发布频率: 30 Hz
         - 坐标系: odom (父) → base_link (子)

      2. /odom (nav_msgs/msg/Odometry) [可选]
         - 包含位姿和协方差
```

#### B. slam_gmapping 节点 (核心)

```
输入:
      1. /scan (sensor_msgs/msg/LaserScan)
         - 来源: laser_driver (真实) 或 rosbag2 (回放)
         - 包含: ranges[] 距离数组, angle_min/max, increment
         - QoS: sensor_data ( Best Effort )

      2. TF: odom → base_link (通过 tf2_ros::Buffer 查询)
         - 来源: odometry_publisher 或真实里程计
         - 按需查询, 不订阅话题

      3. TF: base_link → laser_frame (通过 tf2_ros::Buffer 查询)
         - 来源: robot_state_publisher (URDF 静态 TF)
         - 用于确定激光雷达安装位置

内部处理:
      - tf2_ros::MessageFilter 确保 TF 可用后才处理激光扫描
      - GridFastSLAM 算法处理 (见执行流部分)

输出:
      1. /map (nav_msgs/msg/OccupancyGrid)
         - QoS: transient_local (新订阅者立即收到最新地图)
         - 发布间隔: map_update_interval 参数控制 (默认 5.0s)
         - data[]: -1 (未知), 0 (空闲), 100 (占据)

      2. /map_metadata (nav_msgs/msg/MapMetaData)
         - 地图尺寸、分辨率、原点

      3. /entropy (std_msgs/msg/Float64)
         - 粒子滤波熵, 表示位姿估计的不确定性
         - 值越大 = 越不确定

      4. TF: map → odom
         - 通过 tf2_ros::TransformBroadcaster 发布
         - 发布频率: transform_publish_period 参数控制 (默认 0.05s = 20Hz)
         - 校正 odom 坐标系的累积误差

      5. dynamic_map 服务 (nav_msgs/srv/GetMap)
         - 按需返回当前完整地图
         - 同步阻塞调用
```

#### C. laser_driver 节点

```
输入: 串口 /dev/ttyUSB0 (Camsense X2M 雷达)

处理: SDK 回调 → 点云 → LaserScan 消息

输出: /scan (sensor_msgs/msg/LaserScan)
      - frame_id: laser_frame
      - range_min: 0.05m
      - range_max: 16.0m
```

### 1.3 TF 坐标变换链

```
map ───[gmapping 发布]───→ odom ───[odometry_publisher 发布]───→ base_link ───[robot_state_publisher 发布]───→ laser_frame
 |                              |                                    |                                           |
 SLAM 全局坐标系                里程计坐标系                         机器人基坐标系                                激光雷达坐标系
 (校正后, 无漂移)               (积分累积漂移)                       (机器人中心)                                  (传感器安装位)
```

**关键关系:**
```
T(map → laser_frame) = T(map → odom) × T(odom → base_link) × T(base_link → laser_frame)
```

gmapping 通过扫描匹配计算 `T(map → odom)`, 使不同时刻的激光扫描在全局 map 坐标系下保持一致。

## 二、控制流 (Control Flow)

控制流描述系统**如何被启动、配置和管理**。

### 2.1 系统启动流程

#### 方式一: 一键启动 (complete_slam.launch.py)

```
ros2 launch gmapping complete_slam.launch.py

启动顺序:
┌─────────────────────────────────────────────────────────────────┐
│ 1. robot_state_publisher                                        │
│    ├─ 读取 URDF: robot_state_publisher_pkg/urdf/robot.urdf      │
│    └─ 发布 TF: base_link → laser_frame (静态变换, 100Hz)         │
│                                                                 │
│ 2. odometry_publisher                                           │
│    ├─ 参数: odom_frame=odom, base_frame=base_link, rate=30Hz    │
│    └─ 开始订阅 /cmd_vel, 发布 odom TF (30Hz)                    │
│                                                                 │
│ 3. slam_gmapping (通过 IncludeLaunchDescription)                │
│    ├─ 加载所有 launch 参数 (见参数传递链)                        │
│    ├─ 初始化 GridSlamProcessor                                   │
│    ├─ 创建 Publisher/Subscriber/Service                          │
│    ├─ 启动 tf2_ros::MessageFilter                                │
│    └─ 启动 publishLoop 线程 (20Hz 发布 map→odom TF)             │
└─────────────────────────────────────────────────────────────────┘

完成后系统状态:
  - 等待 /scan 数据
  - 等待 /cmd_vel 数据
  - 就绪, 可开始建图
```

#### 方式二: 单独启动 gmapping

```
ros2 launch gmapping slam_gmapping.launch.py [参数...]

仅启动 slam_gmapping 节点, 需要外部提供:
  - /scan 话题数据 (激光雷达驱动或 rosbag2)
  - odom → base_link TF (里程计)
  - base_link → laser_frame TF (URDF 或静态 TF)
```

#### 方式三: 组件容器模式

```
ros2 run rclcpp_components component_container
ros2 load slam_gmapping_component

优势:
  - 共享进程, 减少通信开销
  - 更好的资源管理
```

#### 方式四: rosbag2 回放

```
ros2 run gmapping slam_gmapping_replay --ros-args \
  -p bag_filename:=/path/to/recording.db3 \
  -p scan_topic:=/scan

控制流:
  - 不创建实时 Subscriber
  - 直接读取 rosbag2 数据库
  - 按时间戳顺序回放激光扫描
  - 其余处理逻辑与实时完全相同
```

### 2.2 参数传递链

```
启动命令 (CLI)
  │
  │ ros2 launch gmapping complete_slam.launch.py \
  │     scan_topic:=scan base_frame:=base_link ...
  ▼
LaunchDescription.generate_launch_description()
  │
  ├─ DeclareLaunchArgument (声明参数)
  │     scan_topic, base_frame, odom_frame, map_frame,
  │     map_update_interval, max_urange, sigma, ...
  │     (共 30+ 个参数)
  │
  ├─ LaunchConfiguration (读取参数值)
  │
  └─ Node(parameters=[{...}])  (传递给节点)
         节点启动时通过 this->declare_parameter<T>() 读取
         未指定的参数使用声明时的默认值
         ↓
      SlamGMapping::init()
         throttle_scans_, base_frame_, map_frame_, odom_frame_,
         map_update_interval_, maxUrange_, sigma_, ...
         (全部成员变量初始化)
```

### 2.3 节点生命周期

```
节点创建 (SlamGMapping 构造函数)
    │
    ▼
init()
    ├─ new GridSlamProcessor          (GMapping 核心算法对象)
    ├─ new tf2_ros::Buffer            (TF 缓冲区)
    ├─ new tf2_ros::TransformListener (TF 监听器)
    ├─ new tf2_ros::TransformBroadcaster (TF 广播器)
    └─ 声明所有 ROS 参数 (declare_parameter)
    │
    ▼
startLiveSlam()
    ├─ 创建 Publisher: /map, /map_metadata, /entropy
    ├─ 创建 Service: /dynamic_map
    ├─ 创建 MessageFilter Subscriber: /scan
    │     └─ 注册回调: laserCallback()
    └─ 启动 publishLoop 线程 (循环发布 map→odom TF)
    │
    ▼
rclcpp::spin(node)  ─── 进入事件循环 ───
    │
    │    事件 1: 收到 /scan 消息
    │         → tf2_ros::MessageFilter 检查 TF 是否可用
    │         → 可用时触发 laserCallback()
    │
    │    事件 2: 收到 /dynamic_map 服务请求
    │         → mapCallback() 返回当前地图
    │
    │    事件 3: publishLoop 线程定时触发
    │         → publishTransform() 发布 map→odom TF
    │
    │    事件 4: Ctrl+C (SIGINT)
    │         → rclcpp::shutdown()
    │         → 节点析构
    │              ├─ 停止 publishLoop 线程 (join)
    │              ├─ 删除 GridSlamProcessor
    │              └─ 清理资源
    ▼
节点退出
```

## 三、执行流 (Execution Flow)

执行流描述系统在**运行时如何处理每一帧数据**, 包括内部算法步骤和条件分支。

### 3.1 激光扫描处理主流程

```
收到 /scan 消息
    │
    ▼
laserCallback(scan)
    │
    ├─ laser_count_++
    ├─ throttle_scans_ 节流检查
    │     if (laser_count_ % throttle_scans_ != 0) return;
    │     默认 throttle_scans_=1, 即每帧都处理
    │
    ▼
首次扫描? (got_first_scan_ == false)
    │
    ├─ YES → initMapper(*scan)
    │         │
    │         ├─ 1. 获取激光雷达坐标系 (scan.header.frame_id)
    │         │
    │         ├─ 2. TF 查询: laser_frame → base_link
    │         │      确定激光雷达安装位置
    │         │      如果失败 → 警告并返回
    │         │
    │         ├─ 3. 验证安装方式: Z 轴必须垂直
    │         │      TF 查询: base_frame 的 Z 轴在 laser_frame 中的投影
    │         │      if |Z| ≠ 1 → 警告 "Laser has to be mounted planar!" → 返回
    │         │
    │         ├─ 4. 确定扫描方向 (顺时针/逆时针)
    │         │      do_reverse_range_ = scan.angle_min > scan.angle_max
    │         │
    │         ├─ 5. 创建 RangeSensor 对象
    │         │      设置光束数量、角度增量、最大量程
    │         │
    │         ├─ 6. 创建 OdometrySensor 对象
    │         │      绑定 odom_frame_
    │         │
    │         ├─ 7. 获取初始位姿
    │         │      TF 查询: laser_frame → odom_frame
    │         │      失败则使用 (0, 0, 0)
    │         │
    │         ├─ 8. 配置 GMapping 参数
    │         │      gsp_->setMatchingParameters(...)    // 扫描匹配
    │         │      gsp_->setMotionModelParameters(...) // 运动模型噪声
    │         │      gsp_->setUpdateDistances(...)       // 更新触发距离
    │         │      gsp_->setUpdatePeriod(...)          // 更新触发时间
    │         │
    │         ├─ 9. gsp_->GridSlamProcessor::init(...)
    │         │      初始化粒子滤波器 (particles_ 个粒子)
    │         │
    │         └─ 10. got_first_scan_ = true
    │
    └─ NO → 继续处理
    │
    ▼
addScan(*scan, odom_pose)
    │
    ├─ 1. getOdomPose(gmap_pose, scan.header.stamp)
    │      │
    │      ├─ TF 查询: laser_frame → odom_frame (在扫描时间戳)
    │      ├─ 提取 (x, y, yaw) → gmap_pose
    │      └─ 失败 → 返回 false (跳过此帧)
    │
    ├─ 2. 验证光束数量
    │      if scan.ranges.size() != gsp_laser_beam_count_ → 返回 false
    │
    ├─ 3. 反转距离数组 (如果安装方向需要)
    │      if do_reverse_range_ → reverse(ranges)
    │      同时将无效读数 (< range_min) 设为 range_max
    │
    ├─ 4. 创建 RangeReading 对象
    │      封装距离数据 + 位姿 + 时间戳
    │
    └─ 5. gsp_->processScan(reading)  ─── 核心算法入口 ───
              │
              ├─ 5.1 运动模型预测
              │       根据里程计位姿变化, 更新所有粒子位姿
              │       加入运动噪声 (srr_, srt_, str_, stt_)
              │
              ├─ 5.2 检查是否需要更新
              │       移动距离 < linearUpdate_ 且
              │       旋转角度 < angularUpdate_ 且
              │       时间间隔 < temporalUpdate_
              │       → 不满足则跳过后面的步骤
              │
              ├─ 5.3 扫描匹配 (ICP)
              │       对每个粒子, 将当前扫描与历史地图对齐
              │       参数: iterations_, lstep_, astep_
              │       输出: 最优位姿修正
              │
              ├─ 5.4 粒子权重计算
              │       根据匹配质量计算每个粒子的权重
              │       权重 = 扫描数据与地图的似然
              │       参数: lsigma_, ogain_
              │
              ├─ 5.5 重采样 (Resampling)
              │       if 有效粒子数 < resampleThreshold_ × 总粒子数
              │       → 按权重重采样, 淘汰低权重粒子
              │
              └─ 5.6 更新地图
                       将最优粒子的扫描数据融合到占据栅格地图
                       (实际地图发布在 mapCallback 中, 见下文)
              │
              └─ 返回 true (处理成功)
    │
    ▼
计算位姿修正
    │
    ├─ 获取最优粒子位姿: mpose = particles[bestIndex].pose
    ├─ 计算激光坐标系下的变换:
    │      laser_to_map = Transform(mpose.theta, mpose.x, mpose.y).inverse()
    │      odom_to_laser = Transform(odom_pose.theta, odom_pose.x, odom_pose.y)
    │
    └─ 计算 map → odom 变换:
           map_to_odom_ = (odom_to_laser × laser_to_map).inverse()
           (此变换存储在成员变量中, 由 publishLoop 线程发布)
    │
    ▼
检查是否需要发布地图
    │
    ├─ 条件: !got_map_ || (scan_time - last_map_update > map_update_interval_)
    │      默认 map_update_interval_ = 5.0 秒
    │
    └─ YES → updateMap(*scan)
              │
              ├─ 1. 创建 ScanMatcher 对象
              │      设置激光参数、最大量程、可用量程
              │
              ├─ 2. 获取最优粒子
              │      best = particles[getBestParticleIndex()]
              │
              ├─ 3. 计算位姿熵 (不确定性)
              │      entropy = -Σ(w_i × log(w_i))
              │      if entropy > 0 → 发布 /entropy 话题
              │
              ├─ 4. 重建地图
              │      遍历最优粒子的轨迹节点树 (TNode):
              │      for each node in trajectory:
              │          computeActiveArea()  // 计算受影响区域
              │          registerScan()       // 注册扫描数据到地图
              │
              ├─ 5. 调整地图尺寸
              │      if 地图尺寸变化:
              │          更新 width, height, origin
              │          重新分配 data[] 数组
              │
              ├─ 6. 生成占据栅格数据
              │      for each cell (x, y) in map:
              │          occ = smap.cell(x, y)
              │          if occ < 0        → data = -1  (未知区域)
              │          if occ > occ_thresh_ (0.25) → data = 100 (占据)
              │          else              → data = 0   (空闲)
              │
              ├─ 7. got_map_ = true
              │
              ├─ 8. 发布地图
              │      sst_->publish(map_.map)           // /map
              │      sstm_->publish(map_.map.info)     // /map_metadata
              │
              └─ 9. last_map_update = scan_time
```

### 3.2 TF 发布线程 (独立线程)

```
publishLoop(transform_publish_period = 0.05s)
    │
    ▼
循环 (while rclcpp::ok()):
    │
    ├─ sleep(transform_publish_period)  // 20Hz
    │
    ├─ publishTransform()
    │      │
    │      ├─ 加锁 map_to_odom_mutex_  (与 laserCallback 共享)
    │      │
    │      ├─ 计算时间戳: tf_expiration = now() + tf_delay_
    │      │
    │      ├─ 构造 TransformStamped:
    │      │      header.frame_id = map_frame_
    │      │      child_frame_id = odom_frame_
    │      │      transform = map_to_odom_
    │      │
    │      └─ tf_broadcaster_->sendTransform(transform_stamped)
    │
    └─ 继续循环...
```

**为什么需要独立线程?**
- `laserCallback` 频率不固定 (取决于激光雷达帧率和 linearUpdate 阈值)
- TF 需要稳定发布 (20Hz+), 否则下游节点会认为 TF 过期
- 避免 TF 发布阻塞激光扫描处理

### 3.3 服务请求处理

```
收到 /dynamic_map 服务请求
    │
    ▼
mapCallback(request, response)
    │
    ├─ 加锁 map_mutex_  (与 updateMap 共享)
    │
    ├─ 检查: got_map_ && map_.map.info.width && map_.map.info.height
    │
    ├─ YES → *response = map_  (拷贝当前完整地图)
    └─ NO  → 返回空响应
```

### 3.4 条件分支汇总

| 条件 | 位置 | 结果 |
|------|------|------|
| `laser_count_ % throttle_scans_ != 0` | laserCallback | 跳过此帧 (节流) |
| `!got_first_scan_` | laserCallback | 执行 initMapper() |
| `initMapper()` 失败 | laserCallback | 返回, 继续等待下一帧 |
| `getOdomPose()` 失败 (TF 不可用) | addScan | 返回 false, 跳过此帧 |
| `scan.ranges.size() != beam_count` | addScan | 返回 false, 跳过此帧 |
| `gsp_->processScan()` 失败 | addScan | 返回 false, 不更新地图和 TF |
| `scan_time - last_map_update < map_update_interval_` | laserCallback | 不发布地图 |
| `resampleThreshold` 达到 | processScan (内部) | 执行粒子重采样 |
| `entropy > 0` | updateMap | 发布 /entropy 话题 |

## 四、关键设计模式

### 4.1 消息过滤 (tf2_ros::MessageFilter)

```
/scan 消息到达
    │
    ▼
MessageFilter 检查:
    - 此时间戳的 odom → base_link TF 是否可用?
    - 此时间戳的 base_link → laser_frame TF 是否可用?
    │
    ├─ YES → 触发 laserCallback()
    └─ NO  → 缓存消息, 等待 TF 到达或超时
```

**作用:** 避免处理激光扫描时因 TF 未就绪而报错, 自动同步多源数据的时间戳。

### 4.2 线程安全

```
共享资源:
    1. map_to_odom_ (tf2::Transform)
       - writer: laserCallback (主线程)
       - reader: publishTransform (独立线程)
       - 保护: map_to_odom_mutex_

    2. map_ (nav_msgs/GetMap::Response)
       - writer: updateMap (主线程)
       - reader: mapCallback (服务回调, 可能在任意线程)
       - 保护: map_mutex_
```

### 4.3 QoS 策略

| 话题 | QoS | 原因 |
|------|-----|------|
| `/scan` | Best Effort (sensor_data) | 激光数据高频, 允许丢帧 |
| `/map` | Reliable + transient_local | 新订阅者需要立即获得最新地图 |
| `/map_metadata` | Reliable + transient_local | 同上 |
| `/entropy` | Reliable + transient_local | 同上 |
| TF 发布 | Reliable | 坐标变换必须可靠 |

## 六、故障排查流程

### 6.1 常见问题与信号流关系

| 症状 | 信号流中断位置 | 排查命令 |
|------|----------------|----------|
| 地图不更新 | `/scan` 未到达 gmapping | `ros2 topic hz /scan` |
| 地图不更新 | `odom→base_link` TF 缺失 | `ros2 run tf2_ros tf2_monitor` |
| 地图不更新 | `initMapper` 失败 (TF: base_link→laser_frame 缺失) | `ros2 run tf2_ros view_frames` |
| 地图扭曲 | `/scan` 时间戳与 TF 不同步 | `ros2 topic echo /scan --once` |
| 地图发布慢 | `map_update_interval` 设置过大 | 检查 launch 参数 |
| TF: map→odom 不发布 | `publishLoop` 线程未启动 | 检查 `transform_publish_period` 参数 |
| 无熵值输出 | 粒子权重全为 0 | 检查粒子数 `particles` 参数 |

### 6.2 完整信号链验证

```bash
# 1. 验证所有话题存在
ros2 topic list | grep -E "scan|map|odom|entropy|cmd_vel"

# 2. 验证 TF 树完整
ros2 run tf2_ros view_frames
evince frames.pdf  # 应看到: map → odom → base_link → laser_frame

# 3. 验证数据流动
ros2 topic hz /scan        # 应 > 0 (激光雷达频率)
ros2 topic hz /map         # 应 ≈ 1/map_update_interval
ros2 topic echo /entropy   # 应 > 0

# 4. 验证 TF 发布
ros2 run tf2_ros tf2_monitor  # 应看到 map→odom 在发布
```
