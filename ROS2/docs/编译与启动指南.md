# ROS2 gmapping 编译与启动指南

> 适用于 `osrf/ros:humble-desktop-full` 镜像，Ubuntu 22.04 (Jammy)

---

## 一、先决条件

### 1.1 系统要求

| 项目 | 要求 |
|------|------|
| 操作系统 | Ubuntu 22.04 (Jammy) |
| Docker | 已安装并配置完成 |
| 磁盘空间 | 至少 10 GB（编译后约 3-5 GB） |
| 内存 | 建议 4 GB 以上（粒子滤波较耗内存） |
| 显示服务器 | X11（用于 rviz2 GUI） |

### 1.2 网络要求

- **ROS2 apt 仓库**: `http://packages.ros.org/ros2/ubuntu` — 中国大陆访问可能不稳定
- **如使用代理**: 需要配置 HTTP/HTTPS 代理，脚本默认代理地址为 `http://127.0.0.1:7897`
- **GitHub 访问**: 需要克隆 `openslam_gmapping` 源码

## 二、快速开始（推荐 — 使用管理脚本）

### 2.1 配置代理（如使用科学上网）

编辑 `ros2_docker.sh`，确认代理地址正确：

```bash
HTTP_PROXY="${HTTP_PROXY:-http://127.0.0.1:7897}"
HTTPS_PROXY="${HTTPS_PROXY:-http://127.0.0.1:7897}"
```

### 2.2 启动容器

```bash
cd /path/to/slam_gmapping/ROS2
chmod +x ros2_docker.sh
./ros2_docker.sh start
```

### 2.3 安装依赖

```bash
./ros2_docker.sh deps
```

脚本会自动：
- 通过代理安装 apt 系统依赖
- 克隆 `openslam_gmapping` 源码到 `src/` 目录（如尚未存在）

### 2.4 编译

```bash
./ros2_docker.sh build
```

### 2.5 进入容器

```bash
./ros2_docker.sh shell
```

容器内工作空间位于 `/root/ros2_ws`，编译产物在 `build/` 和 `install/` 目录。

## 三、手动编译（传统方式）

### 3.1 启动容器并映射本地项目目录

```bash
cd /path/to/slam_gmapping/ROS2
docker run -d \
  --name ros2-gmapping \
  --privileged \
  --network host \
  -e HTTP_PROXY=http://127.0.0.1:7897 \
  -e HTTPS_PROXY=http://127.0.0.1:7897 \
  -e http_proxy=http://127.0.0.1:7897 \
  -e https_proxy=http://127.0.0.1:7897 \
  -e DISPLAY=$DISPLAY \
  -e QT_X11_NO_MITSHM=1 \
  -v /tmp/.X11-unix:/tmp/.X11-unix \
  -v $(pwd):/root/ros2_ws/src \
  -v ~/.ssh:/root/.ssh:ro \
  -w /root/ros2_ws \
  osrf/ros:humble-desktop-full \
  tail -f /dev/null

# 配置 apt 使用代理
docker exec ros2-gmapping bash -c "echo 'Acquire::http::Proxy \"http://127.0.0.1:7897\";' > /etc/apt/apt.conf.d/99custom"
```

### 3.2 进入容器

```bash
docker exec -it ros2-gmapping bash -c "source /opt/ros/humble/setup.bash && bash"
```

### 3.3 安装系统依赖

```bash
# 如果使用了代理，需要设置环境变量
export http_proxy=http://127.0.0.1:7897
export https_proxy=http://127.0.0.1:7897

apt-get update
apt-get install -y \
  ros-humble-nav2-bringup \
  ros-humble-teleop-twist-keyboard \
  ros-humble-slam-toolbox \
  python3-colcon-common-extensions \
  ros-humble-rclcpp-components \
  ros-humble-nav2-msgs \
  ros-humble-rosbag2-cpp \
  ros-humble-rosbag2-storage
```

> **注意**: `ros-humble-openslam-gmapping` **不在** apt 仓库中，需要从源码编译。

### 3.4 克隆 openslam_gmapping 源码

```bash
cd /root/ros2_ws/src
git clone https://github.com/ros-perception/openslam_gmapping.git
```

> **重要**: 该仓库只有 `melodic-devel`（ROS1）分支，但它是**纯 C++ 库**，编译到 ROS2 完全没问题。项目已自带适配 ament_cmake 的 `CMakeLists.txt`。

### 3.5 编译

```bash
cd /root/ros2_ws
source /opt/ros/humble/setup.bash

# 方法一：分步编译（推荐，出错时更容易定位）
# 1. 编译 openslam_gmapping（已配置 -fPIC）
colcon build --packages-select openslam_gmapping --cmake-args -DCMAKE_BUILD_TYPE=Release

# 2. 编译 gmapping
colcon build --packages-select gmapping --cmake-args -DCMAKE_BUILD_TYPE=Release

# 方法二：一次性编译
colcon build --cmake-args -DCMAKE_BUILD_TYPE=Release
```

> **提示**: 如果修改了 Python/launch 文件，建议使用 `--symlink-install`，否则需要手动 `cp` 到 `install/` 或清理 `install/<pkg>` 后重新编译。

### 3.6 加载环境

```bash
source install/setup.bash
```

## 四、启动 — 完整 SLAM 栈（推荐测试）

这是**最简单的测试方式**，一键启动所有需要的组件，无需任何真实硬件。

### 4.1 启动

```bash
# 宿主机执行
./ros2_docker.sh build
./ros2_docker.sh complete_slam
```

这会启动：

| 节点 | 功能 | 输出 |
|------|------|------|
| `robot_state_publisher` | 根据 URDF 发布静态 TF | `base_link` → `laser_frame` |
| `odometry_publisher` | 订阅 `/cmd_vel`，积分计算位姿 | `odom` → `base_link` TF (30Hz) |
| `gmapping` | SLAM 核心，接收 `/scan` + 里程计 | `/map`, `/map_metadata`, `/entropy`, `map`→`odom` TF |

### 4.2 键盘遥控建图

在另一个终端启动遥控：

```bash
./ros2_docker.sh shell
source /root/ros2_ws/install/setup.bash
ros2 run teleop_twist_keyboard teleop_twist_keyboard
```

**按键说明:**

| 按键 | 动作 |
|------|------|
| `i` | 前进 |
| `,` | 后退 |
| `j` | 左转 |
| `l` | 右转 |
| `u` | 前进+左转 |
| `o` | 前进+右转 |
| `m` | 后退+左转 |
| `.` | 后退+右转 |
| `k` | 停止（直线/角速度归零） |

按 `q` 退出遥控。

### 4.3 查看地图（可选）

```bash
# 宿主机执行 — 允许容器访问 X11 显示服务器
xhost +local:docker

# 容器内执行
source /opt/ros/humble/setup.bash
rviz2
```

在 rviz2 中：
1. 点击左下角 **Add** → 选择 **Map**
2. Topic 选择 `/map`
3. 即可看到实时构建的 2D 占据栅格地图

### 4.4 保存地图

```bash
source /root/ros2_ws/install/setup.bash
ros2 run nav2_map_server map_saver_cli -f ~/my_map
```

这会生成两个文件：
- `~/my_map.yaml` — 地图元数据（分辨率、原点、尺寸）
- `~/my_map.pgm` — 地图图像（PGM 格式）

### 4.5 加载保存的地图

```bash
source /opt/ros/humble/setup.bash
ros2 run nav2_map_server map_server --ros-args \
  -p yaml_filename:=/root/my_map.yaml
```

## 六、启动 — 真实机器人模式

> 此模式需要连接激光雷达和底盘，适用于真实机器人。

### 6.1 启动流程

**终端 1** — 启动激光雷达 + gmapping：

```bash
# 启动激光雷达驱动
ros2 launch laser_driver laser_driver.launch.py

# 另一个 shell 启动 gmapping
source /root/ros2_ws/install/setup.bash
ros2 launch gmapping slam_gmapping.launch.py \
  scan_topic:=/scan \
  base_frame:=base_link \
  odom_frame:=odom \
  map_frame:=map
```

**终端 2** — 启动底盘驱动（需要替换为实际驱动）：

```bash
ros2 run your_robot_driver your_driver_node
```

底盘驱动需要发布 `odom` → `base_link` TF。

**终端 3** — 键盘遥控：

```bash
ros2 run teleop_twist_keyboard teleop_twist_keyboard
```

### 6.2 真实机器人信号流

```
遥控器 (/cmd_vel) → 底盘驱动 → 发布 odom→base_link TF
                                       ↓
激光雷达 (/scan) → gmapping → 计算 map→odom TF + 发布 /map
```

## 八、回放 rosbag2 测试

使用已有的 rosbag2 数据测试 gmapping（离线建图）。

### 8.1 使用脚本回放

```bash
./ros2_docker.sh replay /path/to/bag.db3
```

### 8.2 手动回放

```bash
source /root/ros2_ws/install/setup.bash
ros2 run gmapping slam_gmapping_replay --ros-args \
  -p bag_filename:=/path/to/bag.db3 \
  -p scan_topic:=/scan
```

### 8.3 回放原理

- `slam_gmapping_replay` 节点直接读取 rosbag2 数据库（`.db3` 文件）
- 按时间戳顺序回放激光扫描数据
- 处理逻辑与实时完全相同
- 需要 bag 中包含 `/scan` 话题和 `odom` → `base_link` TF

## 十一、自定义 launch 参数

### 11.1 核心参数

```bash
ros2 launch gmapping slam_gmapping.launch.py \
  scan_topic:=/scan \
  base_frame:=base_link \
  odom_frame:=odom \
  map_frame:=map \
  map_update_interval:=5.0 \
  particles:=30 \
  delta:=0.05 \
  max_urange:=16.0
```

### 11.2 完整参数列表

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `scan_topic` | `scan` | 激光扫描话题名 |
| `base_frame` | `base_link` | 机器人基坐标系 |
| `odom_frame` | `odom` | 里程计坐标系 |
| `map_frame` | `map` | 地图坐标系 |
| `map_update_interval` | `5.0` | 地图更新间隔（秒） |
| `max_urange` | `16.0` | 激光最大可用量程（米） |
| `sigma` | `0.05` | 扫描匹配的标准差 |
| `kernel_size` | `1` | 扫描匹配核大小 |
| `lstep` | `0.05` | 线性搜索步长 |
| `astep` | `0.05` | 角度搜索步长 |
| `iterations` | `5` | 扫描匹配迭代次数 |
| `lsigma` | `0.075` | 扫描匹配似然标准差 |
| `ogain` | `3.0` | 似然增益 |
| `lskip` | `0` | 跳过的光束数 |
| `srr` | `0.1` | 线性运动中的线性噪声 |
| `srt` | `0.2` | 线性运动中的角度噪声 |
| `str` | `0.1` | 角度运动中的线性噪声 |
| `stt` | `0.2` | 角度运动中的角度噪声 |
| `linear_update` | `1.0` | 移动超过此距离触发更新（米） |
| `angular_update` | `0.5` | 旋转超过此角度触发更新（弧度） |
| `temporal_update` | `3.0` | 超过此时间强制更新（秒） |
| `resample_threshold` | `0.5` | 重采样阈值 |
| `particles` | `30` | 粒子数 |
| `xmin` / `ymin` | `-50.0` | 地图最小边界（米） |
| `xmax` / `ymax` | `50.0` | 地图最大边界（米） |
| `delta` | `0.05` | 地图分辨率（米/像素） |
| `llsamplerange` | `0.01` | 线性采样范围 |
| `llsamplestep` | `0.01` | 线性采样步长 |
| `lasamplerange` | `0.005` | 角度采样范围 |
| `lasamplestep` | `0.005` | 角度采样步长 |

> 详细算法参数说明见 `项目架构与能力说明.md` 第五节。

## 十三、常见问题

### Q1: apt-get 报错 502 Bad Gateway 或 NOSPLIT

通常是因为科学上网代理不稳定。

**解决方法：**

1. **关闭代理直连**（容器使用 `--network host` 时可能不需要代理）：
   ```bash
   docker exec ros2-gmapping bash -c "http_proxy= https_proxy= apt-get update"
   ```

2. **重试安装**（脚本已自动重试 3 次）：
   ```bash
   ./ros2_docker.sh deps
   ```

3. **修复半安装状态**：
   ```bash
   docker exec ros2-gmapping bash -c "apt --fix-broken install -y"
   ```

### Q2: 编译报错找不到 openslam_gmapping

`openslam_gmapping` 不在 apt 仓库中，需要从源码编译：

```bash
cd /root/ros2_ws/src
git clone https://github.com/ros-perception/openslam_gmapping.git
cd /root/ros2_ws
colcon build --packages-select openslam_gmapping --cmake-args -DCMAKE_BUILD_TYPE=Release
source install/setup.bash
colcon build --packages-select gmapping --cmake-args -DCMAKE_BUILD_TYPE=Release
```

> **注意**: 该仓库没有 `ros2` 分支，使用默认的 `melodic-devel` 即可（纯 C++ 库，无 ROS 依赖）。

### Q3: 编译 gmapping 报 `recompile with -fPIC` 错误

`openslam_gmapping` 编译时需要 `-fPIC` 选项才能链接到共享库。项目已配置此选项，如果手动修改过 `CMakeLists.txt`，请确保包含：

```cmake
add_compile_options(-fPIC)
```

修复后需要清理并重新编译：

```bash
rm -rf build/openslam_gmapping install/openslam_gmapping
colcon build --packages-select openslam_gmapping gmapping --cmake-args -DCMAKE_BUILD_TYPE=Release
```

### Q4: 启动后收不到 /scan 数据

检查话题名是否匹配：

```bash
# 查看当前活跃话题
ros2 topic list | grep scan

# 通过 launch 参数修改
ros2 launch gmapping slam_gmapping.launch.py scan_topic:=your_scan_topic
```

### Q5: TF 变换树不完整

确保 TF 树完整：

```bash
# 查看 TF 树
ros2 run tf2_ros view_frames
evince frames.pdf
```

应看到：`map` → `odom` → `base_link` → `laser_frame`

如果缺少 `base_link` → `laser_frame`，确保 `robot_state_publisher` 正确加载了 URDF。

### Q6: 地图不更新

可能原因：

| 原因 | 排查方法 |
|------|----------|
| 机器人未移动 | 检查 `linearUpdate`/`angularUpdate` 参数，确保移动超过 1.0 米或旋转超过 0.5 弧度 |
| 收不到 /scan | `ros2 topic hz /scan` — 应 > 0 |
| odom TF 缺失 | `ros2 run tf2_ros tf2_monitor` — 应看到 odom→base_link 在发布 |
| initMapper 失败 | 查看 gmapping 日志，检查 base_link→laser_frame TF |

### Q7: 地图保存后找不到

确保 `nav2_map_server` 已安装：

```bash
apt-get install ros-humble-nav2-map-server
```

保存地图：

```bash
ros2 run nav2_map_server map_saver_cli -f ~/my_map
```

### Q8: launch 文件报错 `NameError: name 'str_' is not defined`

这是 launch 文件中 `str` 变量与 Python 内置函数冲突的问题。项目已修复此问题，如果拉取了旧版本代码，请确保 `launch/slam_gmapping.launch.py` 中使用的是 `str_` 而非 `str`。

> **注意**: 如果修改了 launch 文件但错误仍然存在，可能是因为 `colcon build` 没有更新 install 目录。手动同步：
> ```bash
> cp /root/ros2_ws/src/gmapping/launch/slam_gmapping.launch.py \
>    /root/ros2_ws/install/gmapping/share/gmapping/launch/
> ```
> 或使用 `colcon build --symlink-install` 重新编译。

### Q9: 容器内 GUI 程序（rviz2）无法显示

确保：

1. 宿主机执行了：
   ```bash
   xhost +local:docker
   ```

2. 容器启动时挂载了 `/tmp/.X11-unix`：
   ```bash
   -v /tmp/.X11-unix:/tmp/.X11-unix
   ```

3. 容器内环境变量正确：
   ```bash
   echo $DISPLAY  # 应输出 :0 或类似值
   ```

### Q10: colcon build 后修改的 launch/py 文件不生效

`colcon build` 默认不会更新 install 目录中的 Python/launch 文件。

**解决方法：**

```bash
# 方法一：使用 symlink-install（推荐）
colcon build --symlink-install

# 方法二：手动同步
cp /root/ros2_ws/src/gmapping/launch/*.launch.py \
   /root/ros2_ws/install/gmapping/share/gmapping/launch/

# 方法三：清理 install 目录后重新编译
rm -rf /root/ros2_ws/install/gmapping
colcon build --packages-select gmapping
```

### 话题与 TF 汇总

| 话题/服务 | 类型 | 发布者/服务方 |
|-----------|------|---------------|
| `/scan` | `sensor_msgs/msg/LaserScan` | laser_driver 或 rosbag2 |
| `/cmd_vel` | `geometry_msgs/msg/Twist` | teleop_keyboard 或导航栈 |
| `/map` | `nav_msgs/msg/OccupancyGrid` | gmapping |
| `/map_metadata` | `nav_msgs/msg/MapMetaData` | gmapping |
| `/entropy` | `std_msgs/msg/Float64` | gmapping |
| `/odom` | `nav_msgs/msg/Odometry` | odometry_publisher 或里程计 |
| `dynamic_map` | `nav_msgs/srv/GetMap` | gmapping (服务) |

| TF 变换 | 发布者 | 频率 |
|---------|--------|------|
| `map` → `odom` | gmapping | 20Hz |
| `odom` → `base_link` | odometry_publisher 或里程计 | 30Hz |
| `base_link` → `laser_frame` | robot_state_publisher | 100Hz |
