# slam_gmapping 项目架构解读

## 一、项目架构

该项目包含两个 ROS 包：

| 包名 | 类型 | 作用 |
|------|------|------|
| **gmapping** | 核心功能包 | 包含所有源代码，实现 SLAM 节点 |
| **slam_gmapping** | 元包 (metapackage) | 依赖聚合器，依赖 `gmapping` + `openslam_gmapping` |

### 包依赖关系

**gmapping** 的依赖：
- `nav_msgs` — 地图消息类型（OccupancyGrid, MapMetaData, GetMap）
- `openslam_gmapping` — OpenSLAM 库，提供 GridSlamProcessor 核心算法
- `roscpp` — ROS C++ 客户端库
- `tf` — 坐标变换系统
- `nodelet` — Nodelet 插件支持
- `rosbag_storage` — Rosbag 回放功能
- `rostest` (测试依赖)

### 编译产物（3个）

| 目标 | 类型 | 源文件组合 | 用途 |
|------|------|-----------|------|
| `slam_gmapping` | 可执行文件 | `slam_gmapping.cpp` + `main.cpp` | 实时 SLAM 节点 |
| `slam_gmapping_nodelet` | 库 | `slam_gmapping.cpp` + `nodelet.cpp` | Nodelet 插件形式 |
| `slam_gmapping_replay` | 可执行文件 | `slam_gmapping.cpp` + `replay.cpp` | Rosbag 离线回放 |

## 二、硬件需求

### 必需传感器

1. **2D 激光雷达 (LiDAR)**
   - 接口：`sensor_msgs/LaserScan`
   - 安装要求：水平安装（可向上或向下，代码自动检测）
   - 适用型号：Hokuyo、RPLidar、Sick 等输出 2D 扫描数据的雷达
   - 代码会检测激光是否 "planar" 安装（`fabs(fabs(up.z()) - 1) > 0.001` 会警告）

2. **里程计 (Odometry)**
   - 来源：轮式编码器、视觉里程计、IMU 融合等
   - 接口：通过 TF 变换树提供 `odom` → `base_link` 变换
   - 作用：提供运动先验，减少扫描匹配计算量

### TF 坐标帧要求

```
map → odom → base_link → laser_frame
```

**关键参数（默认值）**：
- `base_frame`: `"base_link"` — 机器人基座坐标系
- `odom_frame`: `"odom"` — 里程计坐标系
- `map_frame`: `"map"` — 地图坐标系
- `laser_frame`: 从 LaserScan 消息的 `header.frame_id` 自动获取

## 三、实现功能

### 核心算法：GridFastSLAM (GMapping)

结合了三种技术：

1. **Rao-Blackwellized 粒子滤波器**
   - 每个粒子代表一条可能的机器人轨迹
   - 使用里程计作为运动模型提议分布
   - 默认 30 个粒子，可通过 `particles` 参数调整

2. **ICP 扫描匹配 (Scan Matching)**
   - 将新激光扫描与已有地图对齐
   - 修正里程计累积误差
   - 关键参数：`sigma`, `kernelSize`, `lstep`, `astep`, `iterations`, `lsigma`, `ogain`, `minimumScore`

3. **占据栅格地图构建**
   - 输出 2D 栅格地图，分辨率默认 5cm/像素（`delta` 参数）
   - 每个栅格单元有占据概率值
   - `occ_thresh` (默认 0.25) 以上判定为障碍物

### 输入/输出

| 方向 | Topic/Service | 类型 | 说明 |
|------|---------------|------|------|
| **订阅** | `scan` | `sensor_msgs/LaserScan` | 激光雷达数据 |
| **订阅** | `/tf` | `tf/tfMessage` | 里程计位姿 |
| **发布** | `map` | `nav_msgs/OccupancyGrid` | 占据栅格地图 |
| **发布** | `map_metadata` | `nav_msgs/MapMetaData` | 地图元数据 |
| **发布** | `entropy` | `std_msgs/Float64` | 位姿不确定性（粒子熵） |
| **发布** | `/tf` | `tf/tfMessage` | `map`→`odom` 变换 |
| **服务** | `dynamic_map` | `nav_msgs/GetMap` | 请求当前地图 |

### 更新触发条件

- **线性更新**: `linearUpdate` (默认 1.0 米) — 机器人移动超过此距离才处理新扫描
- **角度更新**: `angularUpdate` (默认 0.5 弧度) — 机器人旋转超过此角度才处理新扫描
- **时间更新**: `temporalUpdate` (默认 -1.0，即禁用) — 每隔此时间强制更新
- **地图更新**: `map_update_interval` (默认 5.0 秒) — 地图重新计算和发布间隔

### 重采样

- `resampleThreshold` (默认 0.5) — 粒子重采样阈值，越高越频繁重采样
- 重采样防止粒子退化，保持粒子多样性

## 四、关键参数汇总

### GMapping Wrapper 参数

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `throttle_scans` | 1 | 每隔 N 个扫描处理一次（1=全部处理） |
| `base_frame` | "base_link" | 机器人基座 TF 帧 |
| `map_frame` | "map" | 地图 TF 帧 |
| `odom_frame` | "odom" | 里程计 TF 帧 |
| `map_update_interval` | 5.0 | 地图更新间隔（秒） |
| `transform_publish_period` | 0.05 | TF 变换发布周期（秒） |

### 激光参数

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `maxRange` | 首次扫描的 range_max - 0.01 | 激光最大有效范围 |
| `maxUrange` | 同 maxRange | 建图使用的最大范围 |
| `minimumScore` | 0 | 扫描匹配最小分数（防止开放空间跳跃） |
| `lskip` | 0 | 跳过的激光束数量（0=使用全部） |

### 运动模型噪声参数

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `srr` | 0.1 | 线性→线性噪声 |
| `srt` | 0.2 | 线性→角度噪声 |
| `str` | 0.1 | 角度→线性噪声 |
| `stt` | 0.2 | 角度→角度噪声 |

### 地图参数

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `xmin/ymin/xmax/ymax` | -100/-100/100/100 | 地图边界（米） |
| `delta` | 0.05 | 地图分辨率（米/像素） |
| `occ_thresh` | 0.25 | 占据阈值（超过判定为障碍物） |
| `particles` | 30 | 粒子数量 |

## 五、核心类结构

**SlamGMapping 类** 是整个项目的核心，封装了 OpenSLAM 的 `GMapping::GridSlamProcessor`：

```cpp
GMapping::GridSlamProcessor* gsp_;       // OpenSLAM 核心处理器
GMapping::RangeSensor* gsp_laser_;       // 激光传感器模型
GMapping::OdometrySensor* gsp_odom_;     // 里程计传感器模型
```

### 三种入口点

1. **main.cpp** — 创建 `SlamGMapping` 对象，调用 `startLiveSlam()`，然后 `ros::spin()`
2. **nodelet.cpp** — 将 `SlamGMapping` 封装为 Nodelet 插件，通过 `PLUGINLIB_EXPORT_CLASS` 注册
3. **replay.cpp** — 从 rosbag 文件离线处理，支持命令行参数 `--bag_filename`, `--scan_topic`, `--seed` 等

## 六、Launch 文件配置

### PR2 机器人示例配置

**文件路径**: `gmapping/launch/slam_gmapping_pr2.launch`

```xml
<remap from="scan" to="base_scan"/>  <!-- PR2 的激光话题名 -->
<param name="map_update_interval" value="5.0"/>
<param name="maxUrange" value="16.0"/>
<param name="particles" value="30"/>
<param name="delta" value="0.05"/>
<param name="xmin/ymin/xmax/ymax" value="-50.0/-50.0/50.0/50.0"/>
```

### 测试场景

测试 Launch 文件位于 `gmapping/test/` 下，涵盖：
- 标准场景 (`basic_localization_stage.launch`) — 使用 `base_scan` 话题
- 回放场景 (`basic_localization_stage_replay.launch`, `basic_localization_stage_replay2.launch`)
- TurtleBot 场景 (`basic_localization_symmetry.launch`) — 使用 `/scan` 话题
- 倒装激光雷达场景 (`basic_localization_upside_down.launch`) — 测试激光雷达倒装支持
- 不同激光束数量场景 (`basic_localization_laser_different_beamcount.test`) — 使用 `base_laser1_scan` 话题

## 七、适用场景

- 室内移动机器人（扫地机器人、服务机器人）
- 结构化环境的 2D 地图构建
- 作为导航栈 (navigation stack) 的前置建图模块
